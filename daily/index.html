工程實戰01

Deno 團隊加入 Cloudflare，公布執行環境與 Deploy 過渡安排 ↗

Deno / Ryan Dahl · 2026-10-09

閱讀完整摘要

Ryan Dahl 宣布 Deno 全體團隊加入 Cloudflare，未來開發將集中於共同平台，不再繼續發展獨立的執行環境與代管服務。 團隊將結合 celld 與 Workers、Durable Objects 團隊的工作，希望讓這套程式設計模型成為建置伺服器的預設方式，無論應用執行於 Cloudflare 網路或自己的基礎設施。 celld 將擴充能力內建於程式設計模型，減少每個應用另行組裝基礎設施的需求。 Deno 執行環境將再獲支援一年，每月發布錯誤修正與安全更新；一年後，團隊將結束其開發，但 Deno 仍維持開源，並歡迎他人接續。 Deno Deploy 將繼續營運六個月後關閉，付費客戶轉往 Cloudflare Workers 可獲遷移支援。 JSR 將持續營運，基礎設施移至 Cloudflare；團隊也會繼續支援 rusty_v8，並推進與 workerd 的整合。 Dahl 表示，AI 特別需要更好的抽象設計，而 Durable Objects 結合低成本無伺服器執行、持久狀態、WebSockets 與高階 JavaScript 介面，這些能力對代理執行框架尤其有用，也正是 celld 聚焦於此的原因。

原文重點

Deno 團隊將未來開發集中於與 Cloudflare 共建的平台。

限制與日期說明

Deno 團隊將於再支援一年後結束執行環境開發；Deno Deploy 將於繼續營運六個月後關閉。

摘要來源
  • https://deno.com/blog/cloudflare

新產品02

Open WebUI 0.12.0 加入即時語音、共享回覆與技能版本歷史 ↗

Open WebUI · 2026-10-10

閱讀完整摘要

Open WebUI發布0.12.0，管理員可把語音通話模式切換為Realtime，透過OpenAI即時語音模型處理閒聊，再把實際問題與任務交給聊天選定的模型，連同對話歷史和工具一起處理。工具要求核准或提問時，使用者仍須在聊天中回答；通話需有Allow Call權限，最長一小時。即時通話可使用綁定骨架的VRM角色，加入待機、聆聽、說話動畫及最多十六種具名手勢，角色嘴型會跟隨語音。共享聊天或資料夾新增Allow replies模式，讓獲分享的人在同一對話接續回覆，並即時顯示訊息與輸入狀態；使用者只能編輯、評分、重新產生或停止自己的訊息。啟用上下文壓縮與原生函式呼叫後，長時間工具執行可在工具回合之間壓縮內容，保留工具呼叫與結果配對，摘要亦包含工具名稱和參數。技能現在可附帶腳本、參考資料與範本，每次儲存留下可比較與還原的版本，並支援ZIP或JSON匯出。版本另加入驗證器應用程式雙因素登入，可由管理員要求所有使用者啟用，並提供十組單次復原碼；OAuth與trusted-header登入可分別設定略過。

原文重點

Open WebUI發布0.12.0，管理員可把語音通話模式切換為Realtime，透過OpenAI即時語音模型處理閒聊，再把實際問題與任務交給聊天選定的模型，連同對話歷史和工具一起處理。

限制與日期說明

工程工具03

Claude Code 2.1.296 新增子代理壓縮設定並修正權限檢查 ↗

Anthropic · 2026-10-09

閱讀完整摘要

Anthropic發布Claude Code 2.1.296，新增子代理的autoCompactWindow設定，讓子代理可比主對話提早壓縮上下文，並可用環境變數統一workflow代理採用的模型，其他子代理則維持各自設定。Read工具加入allow_large選項，在需要整份文字檔且上下文容量足夠時，允許單次讀取超過通常大小限制的檔案。Claude apps gateway的管理政策新增code欄位，可將CLI設定套用至Claude Desktop的Code分頁；同時修正2.1.295引入的回歸問題，讓特定管理設定下已儲存的gateway登入能被採用。修正項目還包括共用逐字稿與除錯紀錄遺漏部分秘密值遮蔽，以及Bash權限檢查自動核准某些先設定再使用BASH_ARGV0的命令，後者現在會要求核准。對非有效UTF-8檔案，Edit與NotebookEdit先前可能把所有非ASCII字元替換掉，現在會拒絕這類編輯。VS Code中的Claude in Chrome改為每個工作階段執行瀏覽器動作前都先詢問，包含以@browser連線的階段；當階段已允許某網站後，不再反覆詢問。版本也把預先傳送的MCP工具描述與伺服器指令預設上限，從2,048字元提高至4,096字元。

Anthropic發布Claude Code 2.1.296，新增子代理的autoCompactWindow設定，讓子代理可比主對話提早壓縮上下文，並可用環境變數統一workflow代理採用的模型，其他子代理則維持各自設定。

工程工具04

Pydantic AI 2.55.0 加入跨次執行對話與統一提示快取 ↗

Pydantic · 2026-10-09

閱讀完整摘要

Pydantic AI發布2.55.0，新增Conversation物件，跨次執行攜帶並儲存對話，各入口接受conversation參數。新增統一cache設定與Caching能力，支援跨供應商提示快取；Anthropic自動快取下，cache=True也快取指令和工具定義，Coder預設啟用提示快取。新增支援影像輸入的OpenAIDecisionsModel，提示快取診斷寫入provider_details；OpenAI Responses預設開啟，Anthropic須另行啟用。耐久執行重新執行時，預設run_id與conversation_id不變；Planning紀錄計畫儲存呼叫，防止復原時重複寫入；Memory紀錄工具呼叫，防止分支DBOS流程重複寫入。FallbackModel記錄每次失敗嘗試的模型、時間、錯誤與用量，被拒回應用量亦列入RunUsage。gpt-realtime與GPT-Live新增hang_up()，由伺服器結束WebRTC通話；retain_audio_max_seconds限制保留音訊。套件要求Python 3.11以上，Python 3.10安裝解析至2.54.0或更早版本；支援Decisions的相關extras將openai最低版本提高至3.26.0。

工程工具06

ttok 1.0 更換預設分詞器，Simon Willison 提醒 GPT-6 尚缺官方確認 ↗

Simon Willison · 2026-10-09

閱讀完整摘要

Simon Willison 發布 ttok 1.0，這項工具可依詞元數量計算及截斷文字。 他表示，升級到先前的 0.4 版並輸入檔案後，發現工具仍預設使用 GPT-4 的分詞器，因此決定更換預設值，並以此推出 1.0。 新版改用 o200k_base 分詞器；ttok --list-models 也會顯示底層 tiktoken 如何處理 gpt-5* 等模型名稱前綴。 Willison 同時提醒，OpenAI 尚未正式確認 GPT-6 與 GPT-5 家族使用相同分詞器。 他引用 William Liu 9 月 26 日的實驗：七個 GPT 模型在同一組 31 個測試樣本上，各自回報合計 44,794 個輸入詞元，且每個樣本的計數均相符。 Liu 的實驗說明明確指出，這是文字輸入計數端點的觀察，未驗證生成或計費用量；計數一致並不能證明底層分詞器完全相同。

本則採較短摘要：以已核對的原文內容與摘要使用範圍為限。

原文重點

ttok 1.0 預設改用 o200k_base，模型列表也會顯示前綴處理方式。

限制與日期說明

Willison 指出，OpenAI 尚未確認 GPT-6 與 GPT-5 使用相同分詞器；Liu 指出計數相同不代表分詞器相同。
